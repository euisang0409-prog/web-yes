# UI 상세 설계

## 개요

요구사항과 표준 지침에 따라 메뉴 구조를 설계하고 시스템 단위의 내·외부 화면과 입력 폼을 설계할 수 있다.

UI 상세 설계에서는 화면 구성뿐 아니라 사용자 흐름, 상호작용, 오류 처리, 접근성, 적용 수준까지 함께 고려하여 설계해야 한다.

---

# UI 시나리오 작성 원칙

## 1. 사용자 상호작용 중심 설계

사용자 상호작용(User Interaction)은 사용자가 목표를 달성하기 위해 시스템과 주고받는 행동과 반응의 흐름을 의미한다.

- 시나리오의 출발점은 항상 사용자 행동이어야 한다.
- 핵심 기능과 서비스별로 사용자의 상호작용 흐름을 정의한다.
- 주요 단계를 시나리오 형태로 설계한다.

---

## 2. 적용 수준 구분

서비스에 적용할 기능이나 UI 요소를 필수, 권장, 우수 수준으로 구분한다.

### 필수
서비스 제공을 위해 반드시 필요한 수준

### 권장
사용자 편의성을 높이기 위해 적용하는 수준

### 우수
더 나은 사용자 경험을 제공하기 위한 고도화 수준

---

## 3. 접근성과 포용성 반영

고령자와 장애인을 포함한 다양한 사용자 환경을 고려하여 설계한다.

### 접근성 적용 요소

#### 라벨 제공
어떤 정보를 입력해야 하는지 명확하게 표시

#### 키보드 제어
Tab, Enter 키만으로도 조작 가능

#### 색상
배경과 글자를 쉽게 구분 가능

#### 오류 안내
오류 원인과 해결 방법 제공

#### 대체 텍스트
이미지와 아이콘에 설명 제공

---

## 4. 상호작용, 피드백, 오류 처리

### 피드백

사용자가 행동한 후 시스템이 제공하는 반응

#### 예시

| 사용자 행동 | 시스템 반응 |
|------------|------------|
| 버튼 클릭 | 메시지 표시 |
| 필수 항목 누락 | 오류 메시지 표시 |
| 서버 오류 | 오류 안내 메시지 표시 |

### 오류 처리 예시

| 상황 | 메시지 | 처리 방법 |
|--------|--------|--------|
| 필수 입력 누락 | XXX를 입력해주세요 | 해당 입력창으로 이동 |
| 로그인 실패 | 아이디 또는 비밀번호가 올바르지 않습니다 | 로그인 화면 유지 |

---

## 5. 공통 요소와 반복 패턴 활용

### 컴포넌트

재사용 가능한 UI 구성 요소

예시

- 버튼
- 입력창
- 메뉴

### 기본 패턴

사용자가 자주 경험하는 화면 흐름

### 스타일 가이드

- 버튼
- 색상
- 폰트
- 용어
- 글자 크기

사용 규칙 정의

---

## 6. 실제 사용자 데이터 기반 구성

다음 자료를 기반으로 시나리오를 작성한다.

- 설문 결과
- 사용자 의견
- 행동 데이터
- 평가 결과

---

## 7. 화면 사용 도움 정보 포함

사용자 안내를 위한 정보를 시나리오에 포함한다.

- 툴팁

# UI 시나리오 문서 작성 요건

#### 핵심 사용자 흐름

사용자가 목표를 달성하기 위해 이동하는 순서

#### 과업 중심 상호작용

사용자가 이루고자 하는 목표

### 대상 사용자

- 기획자
- 디자이너
- 퍼블리셔
- 개발자

---

## 2. 구성 요소

### 개요

- 사용자 목표
- 시나리오 목적

### 사용 흐름

- 단계별 화면 이동
- 상태 변화
- 화면 전환 로직

### UI 요소 구성

- 아이디어 도출
- 설계 방향 탐색

### 상호작용 및 입력 로직

- 버튼 클릭
- 입력 필드
- 오류 처리
- 피드백 흐름

### 접근성 고려 사항

- 웹 접근성 준수
- 키보드 제어
- 명확한 라벨 제공

### 예외 및 오류 시나리오

- 오류 발생 흐름
- 복구 절차
- 안내 메시지

### 적용 수준

- 필수
- 권장
- 우수

---

## 3. 작성 원칙

### 일관된 표현 사용

실제 사용자의 행동 흐름을 기준으로 작성한다.

### 현장 적용 가능

UI 위치, 텍스트, 상태값 등을 구체적으로 명시한다.

- 동의

각 단계별로 필수, 권장, 우수 수준을 구분하여 작성한다.

# UI 상세 내용 설계

## 1. 메뉴 구조 설계

### 요구사항 확인

- 요구사항 검토
- UI 설계서 표지 작성
- 개정 이력 작성

### UI 구조 설계

- 요구사항 재검토
- 프로토타입 재검토

### 메뉴 구조 설계

#### 사이트맵

- 트리 구조
- 도형 구조
- 테이블 구조

#### 프로세스 정의

도형을 활용하여 흐름 정의

### 개발 화면 설계

- 프로토타입 기반 화면 구체화
- 화면 개수 산정
- 화면 ID 부여
- 세부 화면 설계

---

## 2. 내부·외부 화면 및 입력 폼 설계

### 실행 부담 감소

#### 사용자 의도 파악

사용자의 목적을 분석한다.

### 행위 순서 검토

- 사전 행동 목록 작성
- 중요도 구분 (상, 중, 하)
- 이동 횟수 분석
- 화면 이동 최소화 검토

### 평가 부담 감소

#### 키 조작 결과 확인

사용자가 결과를 즉시 인식할 수 있는지 검토

##### 키 조작 예시

- 키보드 입력
- 마우스 클릭
- 버튼 클릭
- 메뉴 선택
- 아이콘 클릭

### 상태 변화 확인

시스템 상태 변화를 쉽게 인식할 수 있는지 확인

### 의도와 결과 일치 여부 검토

사용자 기대와 시스템 결과가 일치하는지 확인

---

## 3. UI 설계 결과 평가

### 반복 평가

#### UI 요소 구현 여부 확인

- 컴포넌트
- 서비스 패턴
- 핵심 UI 요소

#### 화면 흐름 평가

##### 직관성

예시

도서 검색 → 목록 → 상세 → 대여

##### 일관성

- 메뉴 위치
- 버튼 명칭
- 화면 이동
- 오류 메시지
- 검색 결과 형식

#### 시각적 일관성

- 색상
- 서체
- 여백
- 아이콘
- 정렬

#### 반응성

| 상황 | 시스템 반응 |
|--------|--------|
| 버튼 클릭 | 즉시 눌림 표시 |
| 검색 실행 | 로딩 표시 |
| 저장 완료 | 완료 메시지 |
| 오류 발생 | 오류 위치 표시 |

### 프로토타입 단계별 평가

#### 초기 프로토타입

- 메뉴 구조
- 화면 흐름

#### 중간 프로토타입

- 사용성
- 오류 처리
- 상호작용

#### 고도화 프로토타입

- 접근성
- 반응성
- 세부 문구

# 상호작용 시뮬레이션

사용자가 실제로 화면을 조작하는 것처럼 테스트하는 과정

| 컴포넌트 | 사용자 행동 | 결과 |
|----------|----------|----------|
| 로그인 버튼 | 클릭 | 로그인 후 이동 |
| 검색 버튼 | 클릭 | 검색 결과 표시 |

---

## 유사 질문 예시

| 목적 | 질문 |
|--------|--------|
| 메뉴 이해 확인 | 도서를 검색하려면 어디를 누르시겠습니까? |
| 버튼 의미 확인 | 이 버튼을 누르면 어떤 일이 발생합니까? |
| 오류 대응 확인 | 오류 메시지를 이해할 수 있습니까? |
| 흐름 이해 확인 | 다음 단계로 가려면 무엇을 해야 합니까? |

---

## 상황 통제 예시

| 상황 | 확인 사항 |
|--------|--------|
| 검색 결과 없음 | 안내 메시지 이해 여부 |
| 비밀번호 오류 | 오류 원인 파악 여부 |
| 대여 불가 도서 | 상태 인식 여부 |
| 네트워크 오류 | 재시도 방법 인식 여부 |

---

# 평가 결과 반영

| 문제점 | 개선 방안 |
|----------|----------|
| 검색 버튼 찾기 어려움 | 버튼 크기 확대 |
| Enter 검색 불가 | Enter 검색 기능 추가 |
| 대여 완료 확인 어려움 | 완료 팝업 제공 |
| 오류 메시지 모호 | 원인과 해결 방법 제공 |
| 메뉴명 이해 어려움 | 쉬운 용어 사용 |
