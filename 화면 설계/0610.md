# 화면 설계

## 1. 요구사항 확인하기

### 1-1. 요구사항 확인

#### UI 개념
- UI(User Interface) : 사용자가 시스템과 상호작용하는 화면, 버튼, 메뉴 등의 시각적 요소

#### UX 개념
- UX(User Experience) : 사용자가 시스템을 이용하면서 느끼는 전체적인 경험

#### UI/UX 관계
- UI는 사용자가 보는 화면
- UX는 사용자가 느끼는 경험
- 좋은 UI는 좋은 UX를 제공하는 기반이 된다.

#### UI/UX 국제 표준
- ISO 9241-210
- 인간 중심 설계(Human Centered Design)에 대한 국제 표준

## 3. 유용성(Usability)

### 유용성 정의

- 사용자가 목표를 효과적이고 효율적으로 달성할 수 있는 정도

### 유용성이 높은 시스템

- 로그인 버튼을 쉽게 찾을 수 있다.
- 메뉴를 쉽게 찾을 수 있다.
- 검색 결과가 빠르다.

### 유용성이 낮은 시스템

- 메뉴를 찾기 어렵다.
- 버튼 이름을 이해하기 어렵다.
- 절차가 복잡하다.

---

### 사용자 모형과 개발자 모형

#### 사용자 모형(User Model)
- 사용자가 생각하는 시스템 모습

#### 개발자 모형(Developer Model)
- 개발자가 구현한 시스템 모습

두 모델의 차이가 클수록 사용성이 낮아진다.

---

## 3-2. 실행 차(Gulf of Execution)

### 정의
- 사용자가 원하는 행동과 실제 시스템 조작 사이의 차이

### 실행 차를 줄이는 방법

#### 사용 의도 파악
- 사용자의 목표 이해
- 필요한 기능 우선 배치
- 중요한 기능 강조

#### 행위 순서 규정
- 작업 단계를 최소화
- 자연스러운 순서 제공
- 다양한 수행 방법 제공

#### 행위 순서대로 실행
- 직관적 절차 제공
- 적절한 입력 장치 사용
- 취소 기능 제공
- 적절한 기본값 제공

---

## 3-3. 평가 차(Gulf of Evaluation)

### 정의
- 사용자가 시스템 상태를 이해하는 과정에서 발생하는 차이

### 평가 차를 줄이는 방법

#### 빠른 피드백 제공
- 입력 결과 즉시 표시
- 처리 상태 표시

#### 상태 변화 확인 가능
- 변경 사항을 쉽게 인식
- 상태 정보 단순화

#### 결과 확인 가능
- 미리보기 제공
- 결과 확인 기능 제공
