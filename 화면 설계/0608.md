# UI/UX 설계 및 요구사항 분석 지침서

## 1. UI 및 UX의 정의
### UI (User Interface)
- 제품이나 소프트웨어와 상호작용할 때 직접 보거나 조작하는 화면 요소
- 사용자가 눈으로 보거나 손으로 누르는 모든 구성요소

### UX (User Experience)
- 사용자가 소프트웨어를 사용하면서 느끼는 전체적인 경험
- 서비스를 이용하면서 느끼는 편리함, 만족감, 효율성, 즐거움 등을 모두 포함한다.

## 2. 구성 요소
### UI 구성 요소
1. **시각적 디자인(Visual Design):** 사용자가 화면에서 보는 모든 요소 (색상, 글꼴, 아이콘, 이미지, 레이아웃)
2. **상호작용 디자인(Interaction Design):** 사용자의 행동에 대해 시스템이 어떻게 반응하는지 설계 (좋은 상호작용 디자인은 사용자가 어떤 상태인지 쉽게 알 수 있도록 도와줌)
3. **정보구조(Information Architecture):** 정보를 체계적으로 분류하고 배치하는 방법 (사용자가 원하는 정보를 쉽게 찾을 수 있도록 구성)

### UX 구성 요소
1. **사용성(Usability):** 사용자가 얼마나 서비스를 쉽게 이용할 수 있는가
2. **유용성(Usefulness):** 서비스가 사용자의 요구사항을 얼마나 잘 충족하는지
3. **매력도(Desirability):** 서비스가 사용자에게 얼마나 매력적으로 느껴지는가
4. **접근성(Accessibility):** 시각장애인, 청각장애인, 고령자, 색약 사용자 등도 서비스를 사용할 수 있어야 함
5. **신뢰성(Credibility):** 사용자가 서비스와 정보를 얼마나 믿을 수 있는가

## 3. UI/UX의 관계 및 표준
- **관계:** 좋은 UI는 좋은 UX에 도움이 된다. 항상 좋은 UI가 좋은 UX는 아니다.
- **표준:** ISO 9241-210 (사람과 컴퓨터 상호작용 관련 표준, 사용자 중심 설계 분야)

### 사용자 중심 설계를 위한 6가지 원칙
1. 사용자는 설계 과정 전반에 적극적으로 참여한다. (실제 사용자의 의견 수집)
2. 전체 사용자 경험을 고려한다. (기능 동작뿐만 아니라 사용자가 느끼는 감정도 고려)
3. 설계는 반복적으로 이루어져야 한다. (테스트와 수정을 반복하여 UI를 발전시킴)
4. 사용자와 소프트웨어 구축 목표 및 환경을 기반으로 한다.
5. 여러 학문 분야가 함께 협력해야 한다. (기획자, UI 디자이너, UX 디자이너, 개발자, 관리자 등)
6. 사용자 평가에 반드시 포함되어야 한다.

## 4. UI 요구사항 확인하기
- 화면을 설계하기 전에 "사용자가 어떤 화면을 원하며, 어떤 방식으로 사용할 것인가"를 분석하는 과정. 개발 시작 전 요구사항 파악이 필수적임.

### 4-1. 사용자 화면 표준 및 지침 확인
- 국가기관(과학기술정보통신부, 행정안전부, 한국인터넷진흥원 등) 가이드라인 수집 분석
- 접근성, 일관성, 색상과 대비 항목 중심 정리
- 공공기관 사례(정부24, 홈택스 등) 분석을 통한 준수 및 미흡 사례 도출
- 내비게이션 구성 및 콘텐츠 배치 원칙 정리 및 의견 수렴

### 4-2. 국제 UI/UX 표준 규격 분석
- **주요 기관:** ISO, W3C(WCAG 2.2), IEEE 830
- **표준 요약:** 표준 번호, 제정 기관, 핵심 목적, 주요 내용, 적용 유의 사항, 참고 링크 정리
- 국내 적용 사례와 표준별 적용 가능성 및 제약사항 도출

### 4-3. 플랫폼별 디자인 가이드라인 분석
- **플랫폼:** 모바일, 웹, 데스크톱, 스마트워치, TV
- **분석 항목:** 색상, 타이포그래피, 레이아웃, 컴포넌트, 상호작용
- 플랫폼별 공통 요소와 차이점 비교, 사례 분석(화면 구조, 메뉴 구성, 입력 방식 등)

## 5. 유사 응용 소프트웨어 분석
- 5-1. 유사 서비스 선정 및 메뉴/화면 구성 분석
- 5-2. 구성 요소 분석: 사이드바, 다크모드, 카드 레이아웃, 모달 등
- 5-3. 사용자 편의성과 UX 요소(사용성, 유용성, 접근성, 일관성, 만족도) 비교 평가
- 5-4. UI 설계 트렌드와 패턴 도출

## 6. 목표 소프트웨어 UI 요구사항 도출
- 6-1. 구축 목적 및 기능/사용자 분석 (기획서, 제안서, 요구사항 명세서 검토)
- 6-2. 기능 목록 작성 및 유형 분류 (입력, 조회, 수정, 삭제, 통계 기능)
- 6-3. 사용자 식별 및 유형별 사용 목적, 기대 행동 정의
- 6-4. 사용자 환경(기기, OS, 장소, 시간대) 분석
- 6-5. 주요 고려사항: 클릭수 최소화, 명확한 피드백, 색상 대비 확보, 일관성 유지, 접근성 고려
- 6-6. 기능별 사용자 사용 시나리오 작성

## 7. 업무 특성 및 UI 흐름 파악
- 7-1. 화면별 UI 구성 요소(버튼, 폼, 메뉴 등) 목록 작성
- 7-2. UI 흐름도 작성 (화면 간 이동 경로, 예외 상황 처리)
- 7-3. 핵심 기능 상호작용 방식 분석
- 7-4. 디자인 일관성 및 접근성/사용성 평가
- 7-5. 경쟁 소프트웨어 UI 비교 분석

## 8. 사용자 면담 및 설문
- 8-1. 대상자 선정 및 면담 계획 수립
- 8-2. 질문지 작성 (기본정보, 사용경험, 개선 요구사항 등)
- 8-3. 파일럿 면담 진행 및 검증
- 8-4. 본 면담/설문 진행 및 결과 취합
- 8-5. 기능 요구사항과 UI 개선 요구사항 구분 및 태깅
- 8-6. 반복적 불만 사항의 우선순위 도출 및 개선 아이디어 보고서 작성

## 9. UI 요구사항 도출 및 정리
- 9-1. 요청 사항 통합 및 그룹핑
- 9-2. 사용 목적 및 시나리오별 요구사항 도출
- 9-3. 기능/비기능 요구사항 분류
- 9-4. 고유 ID 부여 및 상세 설명 작성
- 9-5. 우선순위, 난이도, 중요도 기준 정의
- 9-6. UI 요구사항 명세서 작성
