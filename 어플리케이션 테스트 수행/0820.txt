애플리케이션 빌드 실행
지속적인 통합(CI : Continuous Intgration) 환경
- 개발 과정 중 지속적으로 개발된 프로그램을 통합, 빌드, 배포하여 애플리케이션 개발 내역 검증, 테스트 할 수 있는 환경
- 통합 빌드 과정 중 테스트 도구, 소스코드 품질 측정 도구 등과 연계할 수 있으며, 자동화된 스케줄 관리를 통해서 지속적이고 반복적인 프로그램 빌드, 테스트를 진행할 수 있다.

빌드 도구
- 애플리케이션 배포 단위, 형식에 따라 소스코드 컴파일, 패키징, 배포하는 스크립트를 제공하고 수행하는 도구 
- Ant, Maven, Gradle

테스트 도구
- 개발된 소스코드를 테스트할 수 있는 테스트 코드를 작성, 동작 시킬 수 있는 도구로 통합 빌드 수행 시 연결할 수 있다.
- JUnit, DBUnit

소스코드 품질 측정 도구(코드 인스펙션)
- 정해진 소스코드 작성 규칙에 따라 소스코드를 점검하고 규칙 위반 여부를 체크하는 도구로, 통합 빌드 수행시 연결할 수 있다.

테스트 커버리지 측정 도구
- 소스코드 내 테스트가 가능한 경로 중 테스트 도구를 통해서 테스트된 커버리지를 측정하는 도구이다.

빌드 스케줄 관리 도구
- 작성된 빌드 스크립트를 정해진 조건, 시간에 기동하고 진행 상태, 수행 결과를 관리하는 도구

2. 테스트 커버리지
- 전체 프로그램의 범위 대비 테스트 수행 시 해당 테스트 수행을 위해 동작된 프로그램의 범위 비율을 의미

라인 커버리지(구문 커버리지)
- 개발 소스의 각 라인이 수행되었는지를 확인하는 측정 지표이다.

분기 커버리지
- 개발 소스의 각 분기문이 수행되었는지를 확인하는 측정 지표이다.
- 만약 소스 내에 if문에 대한 true/false 조건이 있다면 두 가지 모두 테스트되어야 100%로 측정한다

조건 커버리지
- 각 분기문 내에 존재하는 조건식이 모두 테스트 되었는지를 확인하는 측정 지표이다.

애플리케이션 빌드 실행하기 
1. 애플리케이션 빌드 스크립트 작성을 위한 빌드 단위 정의
- 애플리케이션 리소스 중 설치되는 부분과 배포되는 부분을 분리한다
ㄴ 설치를 통해 반영되는 부분(프레임워크 설치, 애플리케이션 설정)과 애플리케이션 배포 시 변경되는 부분(프로그램, 이미지, 파일 등)을 구분한다.

- 애플리케이션 배포를 위해서 공통적으로 우선 배포되어야 하는 부분을 분리한다
ㄴ 모든 프로그램에서 공통적으로 참조하는 라이브러리 또는 공통 모듈이 있는 경우 해당 부분을 별도로 분리한다
ㄴ 라이브러리 또는 공통 모듈은 애플리케이션 배포 시 우선적으로 배포되어야 배포 후에 프로그램 오류를 예방할 수 있다.


- 업무 모듈에 따라서 애플리케이션 배포 단위를 정의한다 
ㄴ 애플리케이션의 내부 업무 단위에 따라서 애플리케이션 배포 단위를 세분화 한다.
ㄴ 각 프로그램별 배포도 가능하지만, 업무 기능 단위, 전체 애플리케이션별로도 배포를 수행할 수 있어야 한다.

- 다수 서버에 동시 배포해야 하는 배포 작업을 정의한다
ㄴ 화면 또는 전문 정보와 같은 리소스를 동시에 여러 서버에 배포해야 하는 작업을 구분한다.
ㄴ 동시 배포하는 작업에 대해서 단시간 내 신뢰성 있는 배포 작업이 필요한 경우 해당 기능에 대해서는 기능 구현 및 검증이 진행되어야 한다

- 빌드 수행 시 버전 규칙을 정의한다
ㄴ 빌드 수행 시마다 해당 빌드 버전에 해당하는 버전을 결정하는 규칙을 정의한다.
- 일반적으로 릴리즈 버전, 개발 버전을 분리하고 Major, Minor, BugFix 유형을 구분하여 버전체계를 정의한다.

2. 애플리케이션 빌드 절차에 따


라 빌드 스크립트 작성
- 정해진 빌드 단위에 따라 빌드 스크립트를 작성한다.,
ㄴ 선정된 빌드 도구의 작성 기준, 작성 단위에 따라서 빌드 스크립트를 작성한다.
ㄴ 전체 애플리케이션 관점에서통합, 전체 빌드가 필요한 경우에 작성되며, 개발자별 개별적인 빌드는 개발 도구에 내장된 빌드 도구를 사용한다.

- 코드 인스펙션 도구를 빌드 스크립트에 연계한다
ㄴ 빌드 스크립트에서 코드 인스펙션 연계 태그를 사용해서 코드 인스펙션 도구를 연결한다

- 테스트 도구를 빌드 스크립트에 연계한다
ㄴ 빌드 스크립트에서 테스트 도구 연계 태그를 사용해서 테스트 도구를 연결한다
ㄴ 상용 제품을 사용하거나 선정된 빌드 도구에 따라서 연결 방식, 호환되는 버전이 상이하므로 사전에 연결 방법, 호환성을 확인한 후 연계한다

- 테스트 커버리지 측정 도구를 빌드 스크립트에 연계한다
ㄴ 테스트 커버리지 측정 도구의 경우, 소스코드 컴파일시 해당 도구의 라이버리를 참조하여 분석 로그를 남기게 되므로 컴파일 부분과 결과 리포팅 부분을 구분하여 작성한다.

- 빌드 스케줄러 관리 도구를 설정한다
ㄴ 빌드 스케줄러 설정을 통해서 자동화된 CI 환경을 구성할 수 있다.
ㄴ 빌드 스케줄러 도구는 일반적으로 별도의 웹 페이지를 갖고 있으며, 설치 및 기동 후 해당 웹페이지에 들어가서 해당 애플리케이션 개발 시 소스 형상관리 도구, 빌드 도구를 연결하여 빌드, 배포 작업을 설정하고 슬케줄링 한다.

애플리케이션 실행 검증
1. 빌드 스케줄 관리 도구 
- 빌드 스케줄 관리 도구의 구성
ㄴ 별도의 웹 애플리케이션으로 구성되어 웹 서버상에 배포되고, 관리자 화면을 통해서 빌드 스크립트, 형상관리 도구 등과 연계되며, 이메일을 통해서 관련 개발자, 관리자들에게 빌드 수행 결과를 제공한다

- 빌드 스켖루 관리 도구의 기능
ㄴ 빌드 작업 스케줄링 : 작업 주기, 시간 설정
ㄴ 빌드 작업 상태 및 이력 관리 : 대기, 진행, 완료, 오류
ㄴ 빌드 도구 연계 관리
ㄴ 빌드 수행 결과 리포팅

애플리케이션 실행 검증하기
1. 작성한 빌드 스크립트를 활용하여 애플리케이션 빌드를 수행하고 결과를 확인한다.
- 개발자별 애플리케이션 빌드를 수행한다
- 애플리케이션 전체 통합 빌드를 수행한다
- 빌드 결과를 확인한다
- 빌드 중 수행된 테스트 수행 결과를 확인한다
- 빌드 중 수행된 테스트 커버리지 결과를 확인한다
- 빌드 중 수행된 코드 인스펙션 점검 결과를 확인한다

2. 빌드 중 발생된 오류 사항을 확인하고 대응한다.
- 빌드 중 발생된 오류 사항을 확인하고 원인을 분석한다
- 오류 사항을 확인하고 대응한다

개발자가 체크아웃한 소스가 남아있는 경우
- 빌드 작업 수행 전에 대상 소스를 모두 체크인 하도록 한다

- 빌드 대상 소스코드 간 상호 참조가 발생되는 경우
- 업무 모듈, 공통 모듈의 호출 기준을 정의하여 모듈 간 상호 참조 발생을 방지한다

공통 파일, 환경 +

설정 파일에 대한 오류
- 빌드 담당자가 빌드 작업 수행 전에 공통 파일, 화니경 설정 파일을 업데이트 하도록 한다 

컴파일 자체 오류가 발생되는 경우
- 개발자가 개발을 완료하지 않고 체크인을 하거나 개발 표준을 미인지하여 컴파일이 불가능한 경우로 해당 개발자에게 즉시 오류 수정 요청을 한다.
