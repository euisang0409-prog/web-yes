# 데이터 조작 프로시저 최적화

## SQL 처리 흐름

### 1. 구문 분석(Parse)

* SQL 문이 이전에 실행된 적이 있는지 확인
* 공유 풀(Shared Pool) 영역을 검색하여 판단

#### 공유 풀(Shared Pool)

* 데이터베이스 메모리 내부의 영역
* 이전에 실행된 SQL 문과 실행 계획이 저장될 수 있음

실행 이력이 있는 경우

* 구문 분석 생략

실행 이력이 없는 경우

* 구문 분석 수행

### 구문 분석이란?

사용자가 작성한 SQL 문장을 DBMS가 이해할 수 있는 형태로 해석하는 과정

예시

```sql
SELECT * FROM EMP WHERE EMPNO = 7369;
```

DBMS는 다음 내용을 확인한다.

* SELECT 문인지 확인
* 문법이 올바른지 확인
* EMP 테이블 존재 여부 확인
* EMPNO 컬럼 존재 여부 확인
* 사용자 권한 확인

### 구문 분석의 3단계

#### 1) 문법 검사(Syntax Check)

* SQL 문법이 올바른지 확인

#### 2) 의미 검사(Semantic Check)

* 테이블, 컬럼 등 실제 객체 존재 여부 확인

#### 3) 권한 검사(Privilege Check)

* 사용자가 해당 객체에 접근 가능한지 확인

---

### 2. 실행 단계(Execute)

* 구문 분석이 완료된 SQL을 실제로 실행하는 단계

#### 실행 계획(Execution Plan)

* SQL을 가장 효율적으로 실행하는 방법
* 옵티마이저가 생성

#### 옵티마이저(Optimizer)

* SQL 실행 방법을 계산하는 역할
* 선택된 실행 방법이 실행 계획

구문 분석이 완료되면 서버 프로세스는 데이터베이스 버퍼 캐시를 검사한다.

#### 데이터베이스 버퍼 캐시(Database Buffer Cache)

* 디스크에서 읽어온 데이터를 임시 저장하는 메모리 공간
* 디스크 접근 속도가 느리므로 메모리에 저장하여 성능 향상

버퍼 캐시에 데이터 존재

* 메모리에서 바로 사용

버퍼 캐시에 데이터 없음

* 데이터 파일에서 읽음
* 버퍼 캐시에 저장
* 이후 사용

#### DML 처리

SELECT가 아닌 DML인 경우

```sql
INSERT
UPDATE
DELETE
```

버퍼 캐시 영역에서 데이터가 수정된다.

변경 내용은 COMMIT 해야 최종 반영된다.

* SELECT 문에서만 수행
* 실행 결과를 사용자(클라이언트)에게 전달하는 단계

# SQL 작성 시 고려사항

## 1. SQL 특성을 충분히 이해해야 한다.

* DBMS별 SQL 작성 방식 차이 이해
* Oracle, MySQL, PostgreSQL 등 차이 존재

---

## 2. 옵티마이저가 실행 계획을 수립한 후 실행된다는 것을 이해해야 한다.

검토 사항

* 인덱스 사용 가능 여부
* 조인 순서 적절성
* WHERE 조건 선택도
* 불필요한 정렬 발생 여부

---

## 3. 실행 계획에 따라 수행 속도가 크게 달라질 수 있다.

동일한 결과를 반환하더라도

* 인덱스 사용 여부
* 조인 순서
* 정렬 방식

등에 따라 성능 차이가 발생한다.

---

## 4. 옵티마이저가 비정상적으로 동작할 경우 실행 계획을 조정해야 한다.

조정 방법

* 인덱스 추가
* SQL 조건 변경
* JOIN 순서 개선
* 힌트(Hint) 사용

### 힌트(Hint)

옵티마이저에게 실행 방법을 개발자가 직접 지시하는 기능

문법

```sql
/*+ */
```

인덱스 사용 지시

```sql
SELECT /*+ INDEX(EMP PK_EMP) */
*
FROM EMP;
```

전체 테이블 스캔 지시

```sql
SELECT /*+ FULL(EMP) */
*
FROM EMP;
```

---

## 5. 옵티마이저가 좋은 실행 계획을 선택할 수 있도록 SQL을 작성해야 한다.

작성 원칙

* 조건을 명확하게 작성
* 불필요한 전체 조회 최소화
* 인덱스를 사용할 수 있는 형태로 작성
* 조인 조건 정확히 작성
* 필요한 컬럼만 조회

예시

좋지 않은 SQL

```sql
SELECT *
FROM EMP;
```

좋은 SQL

```sql
SELECT EMPNO, ENAME
FROM EMP
WHERE DEPTNO = 10;
```

---

## 6. 좋은 SQL은 결과를 추론하고 집합적으로 접근해야 한다.

작성 전 고려사항

* 최종적으로 필요한 데이터는 무엇인가?
* 몇 건 정도 조회될 것인가?
* 어떤 조건으로 데이터를 줄일 수 있는가?
* 조인이 필요한가?
* 정렬이 꼭 필요한가?
* 중복 제거가 필요한가?

SQL은 한 건씩 처리하는 방식이 아니라 집합(Set) 단위로 처리된다는 점을 고려하여 작성해야 한다.
