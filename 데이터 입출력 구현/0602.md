# SQL 성능 최적화 및 SQL*Plus 정리

## SQL 처리 흐름

### 1. 구문 분석(Parsing)

사용자가 요청한 SQL 문이 데이터베이스에서 처음 사용된 문장인지, 이미 사용된 문장인지를 공유 풀(Shared Pool) 영역에서 검색하여 확인한다.

### 공유 풀(Shared Pool)

* SQL 문과 실행 계획을 저장하는 메모리 영역
* 동일한 SQL이 다시 실행되면 구문 분석 과정을 생략할 수 있다.

이미 사용된 SQL

* 공유 풀에서 SQL과 실행 계획을 재사용

처음 사용된 SQL

* 구문 분석 수행

### 구문 분석 수행 내용

예시

```sql
SELECT NAME
FROM MEMBER
WHERE MEMBER_ID = 1;
```

확인 항목

* SELECT 문법이 올바른가
* MEMBER 테이블이 존재하는가
* NAME 컬럼이 존재하는가
* MEMBER_ID 컬럼이 존재하는가
* 사용자가 조회 권한을 가지고 있는가

### 옵티마이저(Optimizer)

* SQL을 가장 효율적으로 실행할 방법을 결정하는 데이터베이스 내부 기능
* 실행 계획(Execution Plan)을 생성한다.

---

### 2. 실행(Execute)

구문 분석이 완료된 SQL을 실제 수행하는 단계이다.

서버 프로세스는 데이터베이스 버퍼 캐시(Data Buffer Cache)에서 필요한 데이터를 검색한다.

### 데이터베이스 버퍼 캐시(Data Buffer Cache)

* 실제 테이블 데이터를 저장하는 메모리 영역

동작 과정

1. 버퍼 캐시에 데이터 존재

   * 메모리에서 바로 사용

2. 버퍼 캐시에 데이터 없음

   * 데이터 파일에서 읽음
   * 버퍼 캐시에 저장
   * 이후 요청부터 재사용

INSERT, UPDATE, DELETE 문은 버퍼 캐시의 데이터를 변경한다.

---

### 3. 추출(Fetch)

실행 결과를 사용자에게 전달하는 단계이다.

* 서버 프로세스가 버퍼 캐시의 데이터를 읽음
* 사용자 클라이언트로 결과 전송

참고

* SELECT 문에서만 추출 단계가 수행된다.

---

## SQL 작성 시 고려사항

* SQL 특성을 충분히 이해하고 작성해야 한다.
* 옵티마이저의 실행 계획에 따라 성능 차이가 크게 발생한다.
* 실행 계획을 분석하고 필요 시 조정할 수 있어야 한다.
* 옵티마이저가 좋은 실행 계획을 수립하도록 SQL을 작성해야 한다.
* 결과 집합 중심의 집합 처리 방식으로 SQL을 작성해야 한다.

# SQL 성능 최적화 도구

## TKPROF

### 개요

SQL Trace 파일을 사람이 읽기 쉬운 형태로 변환하는 성능 분석 도구

### SQL Trace

Oracle 데이터베이스에서 SQL이 실제로 수행된 과정을 기록하는 기능

기록 정보

#### Parse

* SQL 분석 단계
* 문법 검사
* 실행 계획 생성

#### Execute

* SQL 실행 단계
* 실제 SQL 수행

#### Fetch

* 조회 결과 반환 단계

### SQL Trace 활성화

```sql
ALTER SESSION SET SQL_TRACE = TRUE;
```

### SQL 실행

```sql
SELECT *
FROM EMP
WHERE EMPNO = 7369;
```

### SQL Trace 비활성화

```sql
ALTER SESSION SET SQL_TRACE = FALSE;
```

### 결과

* Trace 파일(.trc) 생성
* TKPROF를 사용하여 분석

## EXPLAIN PLAN

### 개요

SQL 문의 액세스 경로와 실행 계획을 분석하는 도구

### 특징

* 옵티마이저가 생성한 실행 계획 확인
* 인덱스 사용 여부 확인
* 테이블 접근 방식 확인
* 성능 개선 방향 도출

### 실행 계획 저장 테이블

```text
PLAN_TABLE
```

# SQL*Plus

# SQL*Plus 명령어

## 파일 관련

### SAVE

버퍼 내용을 파일로 저장

```sql
SAVE test.sql
```

### GET

파일 내용을 SQL 버퍼로 불러옴

```sql
GET test.sql
```

### SPOOL

실행 결과를 파일에 저장

```sql
SPOOL result.txt
```

```sql
SPOOL OFF
```

# PL/SQL 테스트

## 테스트 항목

### 실행 여부

* 문법 오류 없이 실행되는지 확인

### 출력 확인

* 예상한 값이 출력되는지 확인

### 데이터 변경 확인

* INSERT
* UPDATE
* DELETE

결과 확인 후 COMMIT 수행

### 오류 확인

```sql
SHOW ERRORS
```

### 조건 테스트

* 정상값
* NULL
* 잘못된 값
* 경계값

# 저장 객체 비교

## Stored Function

특징

* 반드시 값을 반환
* RETURN 사용
* 계산 결과 반환

예시

```sql
FUNCTION GET_TOTAL
RETURN NUMBER
```

---

## Stored Procedure

특징

* 특정 작업 수행
* 반환값 필수 아님
* INSERT, UPDATE, DELETE 작업 수행

예시

```sql
PROCEDURE UPDATE_SAL
```

---

## Trigger

특징

* 특정 이벤트 발생 시 자동 실행

활용 예시

```text
회원 삭제
→ Trigger 자동 실행
→ 삭제 시간 및 회원번호 저장
```
