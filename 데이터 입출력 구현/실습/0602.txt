* Stored Procedure

정답

Stored Function

* 반드시 값을 반환한다.
* RETURN을 사용한다.
* 계산 결과나 특정 값을 반환할 때 사용한다.

[문제 3]

다음은 공유 풀(Shared Pool)과 데이터베이스 버퍼 캐시(Data Buffer Cache)에 대한 설명이다.

대량의 회원을 조회하는 동일한 SQL문이 반복해서 실행될 때, 두 메모리 영역이 SQL 처리 흐름(구문 분석, 실행, 추출) 단계에서 각각 성능 최적화에 어떻게 기여하는지 메커니즘을 비교하여 서술하시오.

정답

공유 풀(Shared Pool)

* 이전에 실행된 SQL문과 실행 계획을 저장하고 있으므로 동일한 SQL이 다시 실행될 경우 문법 검사, 객체 확인, 실행 계획 생성 등의 구문 분석 과정을 생략할 수 있다.
* 이를 통해 Parsing 비용을 줄여 성능을 향상시킨다.

데이터베이스 버퍼 캐시(Data Buffer Cache)

* 디스크에서 읽어온 데이터를 메모리에 저장한다.
* 동일한 데이터를 다시 조회할 경우 디스크 I/O 없이 메모리에서 바로 데이터를 읽어올 수 있다.
* 이를 통해 실행 속도를 크게 향상시킨다.

[문제 4]

APM 리소스 모니터링 화면에서는 CPU 20%, 메모리 40%로 매우 정상적인 수치를 보이고 있으나, 실제 사용자는 "주문 완료 화면이 넘어가는 데 8초 이상 걸린다"며 불편을 겪고 있습니다.

이 현상이 발생할 수 있는 원인을 엔드투엔드(E2E) 모니터링 관점에서 분석하고, 성능 개선을 위해 개발자가 확인해야 할 내부 유틸리티 2가지를 제시하시오.

정답

원인 분석

* CPU와 메모리 사용량은 정상적이지만 주문 처리 과정 내부에서 병목이 발생했을 가능성이 있다.
* E2E 관점에서는 외부 결제 API 응답 지연, 문자 발송 서버 지연, 데이터베이스 락(Lock), 비효율적인 SQL 실행 계획 등으로 인해 응답 시간이 증가할 수 있다.
* 따라서 서버 자원만으로는 문제를 확인할 수 없으며 전체 트랜잭션 흐름을 추적해야 한다.

확인해야 할 유틸리티

1. TKPROF

* SQL Trace 파일을 분석하여 Parse, Execute, Fetch 단계의 수행 시간과 자원 사용량을 확인한다.
* 성능이 저하되는 SQL을 식별할 수 있다.

2. EXPLAIN PLAN

* SQL 실행 계획을 확인한다.
* 인덱스 사용 여부, Full Table Scan 발생 여부 등을 분석하여 성능 문제를 파악할 수 있다.
