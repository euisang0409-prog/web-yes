이 두 제약조건의 개념과 위배되지 않기 위한 세부 규칙을 비교하여 서술하시오.

6. 논리 데이터 저장소 확인 단계에서는 관계형 데이터 모델의 설계 품질을 높이기 위해 '정규화(Normalization)' 과정을 검토합니다.

1정규형(1NF) : 모든 테이블의 값이 원자값이어야 한다.

2정규형(2NF) : 1정규형을 만족하면서, 기본키가 아닌 모든 속성이 기본키에 완전 함수적 종속을 만족해야 한다.

3정규형(3NF) : 2차 정규형을 만족하고, 기본키가 아닌 모든 속성이 기본키에 이행함수적 종속을 만족하지 않아야 한다.

이 과정에서 1:N(일대다) 관계를 가진 두 개체가 테이블로 변환될 때 외래키(Foreign Key)가 지정되는 규칙을 서술하시오.

46. 사용자가 쿼리를 날렸을 때, '구문 분석(Parsing) 단계'에서 '공유 풀(Shared Pool)'이 수행하는 핵심 역할과, 만약 동일한 쿼리가 공유 풀에 존재할 때 얻을 수 있는 성능적 이점을 하드 파싱(Hard Parsing)의 생략 관점에서 서술하시오.

공유풀이 수행하는 역할
- 데이터베이스 메모리 내에서 이전에 실행된 SQL문과 최적의 경로 정보인 실행 계획을 임시로 보관하는 보관함 역할

성능적 이점
- 동일한 쿼리가 이미 공유 풀에 저장되어 있다면, 옵티마이저가 문법 검사, 오브젝트 권한 확인, 실행 계획을 처음부터 다시 새로 생성할 필요가 없다.
- 구문 분석 속도가 많이 단축된다.


47. 프로시저 내부의 SELECT 문이 실행될 때, 서버 프로세스가 디스크가 아닌 메모리 영역인 데이터베이스 버퍼 캐시(Database Buffer Cache)에서 데이터를 찾았을 때와 찾지 못했을 때의 물리적 처리 과정의 차이점을 데이터 파일(Data File)과 속도 관점에서 비교 서술하시오.

버퍼캐시에 데이터가 있을 때
- 버퍼 캐시에서 데이터를 즉시 읽어 클라이언트로 반환하므로 물리적 I/O 자원을 쓰지 않아서 처리 속도가 매우 빠르다.

버퍼캐시에 데이터가 없을 때
- 디스크에 실제 저장된 물리파일인 데이터 파일에서 관련된 테이블 블록을 직접 읽어와야 하므로 속도가 느리다.
- 이 때 읽어온 데이터는 향후 재사용을 위해 다시 버퍼 캐시에 임시 저장된다.
